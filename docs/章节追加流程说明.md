> （`rename-course`）、概览查询（`list-courses`）的完整说明不在本文范围，
> 仅在涉及追加结果核对时引用。

> - **源码推导**：git 提交 `f336266`（工作区干净）的 `course_progress/core.py`、

## 2. 调用形式与数据库文件规则

子命令形式（`__main__.py:53-58`）：

```bash
python -m course_progress --db <数据库文件> append-chapter <课程编号> --chapter <章节名>
```

- `--db` 写在子命令**前或后均可**：全局 `--db` 定义于 `__main__.py:29`，各子命令
  又各自定义同名参数（`append-chapter` 处为 `__main__.py:56`）。实测两种写法
  均成功（见第 3.3 节；测试 `test_db_option_after_subcommand` 同样覆盖）。
- **父目录必须预先存在**：`connect`（`core.py:34-38`）直接调用
  `sqlite3.connect(db_path)`，不会创建缺失的目录。实测父目录不存在时：
  标准错误 `无法打开数据库：unable to open database file`，退出码 1
  （`__main__.py:84-88`）。
- **数据库文件不存在时会自动建库建表**：`connect` 在打开后执行 `_SCHEMA`
  （`core.py:11-22`）中的 `CREATE TABLE IF NOT EXISTS courses/chapters`。
  注意这一动作发生在任何追加校验之前（`main` 先 `connect` 再分派，
  `__main__.py:85` 先于 `:120`），与第 6 节的边界说明相关。
- 不提供 `--db` 时：标准错误 `必须通过 --db 指定数据库文件`，退出码 2
  （`__main__.py:80-83`），不接触任何文件。

## 3. 成功流程（实测示例）

前提：编号 1 的课程「入门培训」已有两章「准备」「学习」。该前提本身由
`add-course` 建立（实测：`add-course --title "入门培训" --chapter "准备"
--chapter "学习"` 输出 `{"course_id": 1}`，退出码 0）；本文只把它作为前提，
不展开登记流程。

### 3.1 追加章节「 回顾 」（首尾各带一个空格）

```bash
python -m course_progress --db data/course.db append-chapter 1 --chapter " 回顾 "
```

实测结果：

- 标准输出（仅一行）：`{"course_id": 1, "chapter_count": 3}`
  （即 `course_id` 为 1、`chapter_count` 为 3 的一行 JSON；
  `json.dumps` 默认分隔符使冒号后带空格，见 `__main__.py:129`）
- 标准错误：空
- 退出码：0

### 3.2 随后查询详情

```bash
python -m course_progress --db data/course.db get-course 1
```

实测结果：

- 标准输出（仅一行）：
  `{"course_id": 1, "title": "入门培训", "chapters": ["准备", "学习", "回顾"]}`
- 标准错误：空；退出码：0

要点：课程**编号与标题保持原值**；章节列表为 `["准备", "学习", "回顾"]`——
新章节去首尾空白后排在原列表**末尾**，原有章节的名称与顺序不变。

### 3.3 `--db` 写在子命令后（实测）

```bash
python -m course_progress append-chapter 1 --chapter "复习" --db data/course.db
```

实测输出 `{"course_id": 1, "chapter_count": 4}`，退出码 0，与 `--db` 前置
写法行为一致。

## 4. 成功行为说明（源码推导 + 实测核对）

对应函数：`course_progress/core.py:111-149` 的 `append_chapter`。

1. **名称只去首尾空白**：`name = (name or "").strip()`（`core.py:125`）。
   内部空白与大小写原样保留。源码推导：除这一处 `strip()` 外没有任何对名称的
   规范化。实测佐证：测试 `test_append_preserves_inner_spaces_and_case` 用
   `"  阶段  复习  "` 追加后读回 `"阶段  复习"`（内部双空格保留）。
2. **重名比较仅限同一课程，且区分大小写**：`existing` 只查
   `WHERE course_id = ?`（`core.py:134-141`），再用普通 Python 字符串
   `in` 比较（`core.py:142`），故大小写敏感、且其他课程的同名章节不影响。
   实测佐证：测试 `test_same_name_in_other_course_does_not_conflict`（编号 1
   已有「学习」，向编号 2 追加「学习」成功）与
   `test_duplicate_comparison_is_case_sensitive`（已有 `Reading` 时可追加
   `reading`）。
3. **新章节排在末尾**：`position = len(existing)`（`core.py:144`），即接在
   现有最大位置之后；查询侧 `get_course` 按 `ORDER BY position`
   （`core.py:165-171`）返回，因此顺序稳定。
4. **重开同一数据库后顺序不变**：写入在 `with conn:` 事务中提交
   （`core.py:126-148`），落盘为普通 SQLite 文件；新进程对同一 `--db`
   路径查询得到相同顺序。实测：第 3.1 节追加的进程退出后，第 3.2 节另起
   进程查询，章节顺序仍为 `["准备", "学习", "回顾"]`。测试
   `test_append_persists_at_end_with_name_stripped` 同样以跨进程方式验证。
5. **概览章节数增至 3**：`list_courses` 的 `chapter_count` 来自
   `COUNT(ch.position)`（`core.py:71-79`）。实测追加后
   `list-courses` 输出
   `{"courses": [{"course_id": 1, "title": "入门培训", "chapter_count": 3}]}`。
6. **其他课程不受影响**：追加只向 `chapters` 插入一行
   （`core.py:145-148`），不改 `courses` 表，也不触碰其他 `course_id`
   的章节行。测试 `test_append_persists_at_end_with_name_stripped` 与
   `test_db_option_after_subcommand` 均断言编号 2 的课程详情与概览完全不变。

## 5. 失败示例（均为实测）

以下每条均实测：标准输出为空、标准错误只有一行中文消息（无异常堆栈）、
退出后原课程详情与概览保持不变（测试 `assert_append_failure` 对每条失败
都断言这三点，见 `tests/test_append_chapter.py:137-151`）。

### 5.1 编号不是正整数：退出码 2

| 输入（`append-chapter` 后部分） | 标准错误 | 退出码 |
| --- | --- | --- |
| `0 --chapter "回顾"` | `课程编号必须为正整数` | 2 |
| `-3 --chapter "回顾"` | `课程编号必须为正整数` | 2 |
| `abc --chapter "回顾"` | `课程编号必须为正整数` | 2 |

机制：`parse_positive_int`（`__main__.py:69-75`）先 `strip()`，再用
`[+-]?\d+` 做 fullmatch，最后要求 `> 0`；失败时 `main` 在
`__main__.py:105-108` 直接报错，**不进入** `append_chapter`。

### 5.2 课程不存在：退出码 1

| 输入 | 标准错误 | 退出码 |
| --- | --- | --- |
| `42 --chapter "回顾"` | `课程不存在` | 1 |
| `9223372036854775808 --chapter "回顾"` | `课程不存在` | 1 |

机制：`append_chapter` 开头对超出 SQLite 64 位有符号整数范围的编号直接
返回 `None`（`core.py:123-124`，避免 `OverflowError`），范围内则查
`courses` 表无此行返回 `None`（`core.py:127-131`）；CLI 在
`__main__.py:126-128` 输出 `课程不存在`。因此 `9223372036854775808`
（= 2^63，超出 int64 上限）与普通的未知正整数走同一「课程不存在」路径，
实测确认退出码 1、无堆栈。

### 5.3 课程存在但章节名为空：退出码 1

| 输入 | 标准错误 | 退出码 |
| --- | --- | --- |
| `1`（省略 `--chapter`） | `章节不能为空` | 1 |
| `1 --chapter "   "`（名称只有空白） | `章节不能为空` | 1 |

机制：省略 `--chapter` 时 argparse 给出 `None`（`__main__.py:58` 未设
`required`），`core.py:125` 的 `(name or "").strip()` 将其归一为 `""`；
`core.py:132-133` 抛 `ValidationError(ERR_EMPTY_CHAPTER)`，CLI 在
`__main__.py:123-125` 捕获并输出消息。

### 5.4 与已有章节重名：退出码 1

| 输入 | 标准错误 | 退出码 |
| --- | --- | --- |
| `1 --chapter "准备"` | `章节名重复` | 1 |
| `1 --chapter " 准备 "`（去首尾空白后重名） | `章节名重复` | 1 |

机制：`core.py:134-143`，按去首尾空白后的名称与**同一课程**已有章节做
大小写敏感比较。

### 5.5 多问题并存时只报告首个错误

判定顺序为：**编号格式 → 课程存在性 → 章节非空 → 重名**。实测：

| 输入 | 实际报告 | 退出码 |
| --- | --- | --- |
| `0`（非法编号 + 缺 `--chapter`） | `课程编号必须为正整数` | 2 |
| `42 --chapter "   "`（未知编号 + 空名称） | `课程不存在` | 1 |
| `42 --chapter "准备"`（未知编号 + 会重名的名称） | `课程不存在` | 1 |
| `1 --chapter "  "`（空名称，且去空白后不会进入重名判定） | `章节不能为空` | 1 |

源码依据：编号解析在 `__main__.py:105-108`（先于一切）；`append_chapter`
内依次是范围检查（`core.py:123-124`）、存在性（`:127-131`）、非空
（`:132-133`）、重名（`:134-143`）。测试
`test_bad_id_reported_before_other_errors`、
`test_unknown_id_reported_before_blank_or_duplicate_chapter`、
`test_empty_chapter_reported_before_duplicate` 分别覆盖这三条优先级。

## 6. 重复提交与「不留下数据」的边界

- **成功后重复提交相同名称会报重名**：第 3.1 节已把「回顾」追加到编号 1，
  实测再次执行 `append-chapter 1 --chapter "回顾"`，标准错误 `章节名重复`、
  退出码 1、标准输出为空；随后 `get-course 1` 仍为
  `["准备", "学习", "回顾"]`，**不会再增加章节**。测试
  `test_repeated_submission_fails_as_duplicate` 覆盖此情形。
- **失败不新增数据行**：所有校验（存在性、非空、重名）都发生在唯一的
  `INSERT`（`core.py:145-148`）之前，且写入与校验同处一个 `with conn:`
  事务。失败时 `courses` 与 `chapters` 两表不新增任何行——测试
  `assert_state_unchanged`（`tests/test_append_chapter.py:147-151`）在每条
  失败后重新查询两门课程详情与概览逐一比对。
- **但可能已创建空数据库文件及表**：`connect` 先于任何校验执行
  （`__main__.py:85` 先于 `:120`；建表 DDL 在 `core.py:11-22,36-37`）。
  实测：对一个全新路径执行一次**失败**的 `append-chapter`（报
  `课程不存在`）后，该 `.db` 文件已被创建，内含 `courses`、`chapters`、
  `sqlite_sequence` 三张表，且两表均为 0 行。即「不新增数据行」不等于
  「不创建数据库文件和表」；若父目录不存在，则连文件也不会创建
  （实测报 `无法打开数据库：unable to open database file`，退出码 1）。
