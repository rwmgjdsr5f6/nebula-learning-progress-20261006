## 2. 调用形式与数据库定位

与登记、查询完全相同的约定（README 第 7 行对整体 CLI 有记载，源码同样适用）：

- 通过 `python -m course_progress` 调用，每次用 `--db` 指定数据库文件。
- **父目录必须预先存在**；数据库文件不存在时会自动建库建表
  （`core.py:34-38` 的 `sqlite3.connect(db_path)` + `_SCHEMA` 建表脚本）。
  实测父目录不存在时：stderr `无法打开数据库：unable to open database file`，
  退出码 1（`__main__.py:84-88` 对 `connect` 的 `sqlite3.Error` 捕获）。
- **`--db` 写在子命令前后均可**：全局 `--db` 定义于 `__main__.py:29`，
  `append-chapter` 子命令级的 `--db` 定义于 `__main__.py:56`；测试
  `tests/test_append_chapter.py:203-209`（`test_db_option_after_subcommand`）
  覆盖子命令后的写法，本文第 3 节的实测也验证了两种形式。
- 子命令语法（`__main__.py:53-58`）：

  ```
  append-chapter <course_id> [--chapter <章节名>]
  ```

  `course_id` 为位置参数；`--chapter` 为可选标志（省略时按空章节处理，见第 5 节）。

## 3. 成功示例：为「入门培训」追加「回顾」

前提：编号 1 的课程「入门培训」已有两章「准备」「学习」（可由
`add-course --title "入门培训" --chapter "准备" --chapter "学习"` 登记得到，
登记流程见既有说明文档）。以下两条命令为完整流程，均在仓库根目录执行。

### 3.1 追加章节

```bash
python -m course_progress --db data/course.db append-chapter 1 --chapter " 回顾 "
```

注意传入的章节名首尾各带一个空格。实测结果：

- 标准输出**仅一行** JSON，退出码 **0**，标准错误为空：

  ```json
  {"course_id": 1, "chapter_count": 3}
  ```

  如实注明：`json.dumps` 默认分隔符使实际字节中冒号后带空格（`__main__.py:129`）；
  测试按解析后的 JSON 比较，不限定键序与空格
  （`tests/test_append_chapter.py:128-134`），即 `{"course_id":1,"chapter_count":3}`
  与上面是同一内容的两种书写。
- `chapter_count` 是追加后该课程的章节总数：返回值在 `core.py:149` 由
  `position + 1` 得出，新章节位置 `position` 取追加前已有章节数（`core.py:144`）。

### 3.2 随后查询详情

```bash
python -m course_progress --db data/course.db get-course 1
```

实测标准输出（退出码 0，标准错误为空）：

```json
{"course_id": 1, "title": "入门培训", "chapters": ["准备", "学习", "回顾"]}
```

- 课程编号与标题保持原值；章节列表为 `["准备", "学习", "回顾"]`——追加的
  「回顾」已**去除首尾空白**并排在**末尾**。
- 对应测试：`tests/test_append_chapter.py:153-181`
  （`test_append_persists_at_end_with_name_stripped`），它用独立子进程验证
  追加进程退出后重新查询，编号 1 只在末尾多了去空白后的章节，编号 2 完全不变，
  概览中编号 1 的 `chapter_count` 变为 3。

### 3.3 持久化与相互隔离（源码推导 + 实测）

- **重开同一数据库顺序仍然相同**：章节写入普通 SQLite 文件并在 `with conn:`
  事务中提交（`core.py:126,145-148`）；详情查询按
  `SELECT name FROM chapters WHERE course_id = ? ORDER BY position`
  （`core.py:165-171`）取回，顺序由 `position` 列决定，不依赖行的物理顺序。
  实测追加进程退出后另起 `get-course 1`，输出与 3.2 完全一致。
- **概览章节数增至 3**：`list-courses` 的 `chapter_count` 来自对 `chapters`
  的 `COUNT`（`core.py:65-83`），追加后实测返回
  `{"courses": [{"course_id": 1, "title": "入门培训", "chapter_count": 3}]}`。
- **其他课程不受影响**：追加的 INSERT 只写入目标 `course_id` 的一行
  （`core.py:145-148`）；测试 `tests/test_append_chapter.py:168-169` 断言
  另一门课程详情逐项不变，`:211-218`
  （`test_same_name_in_other_course_does_not_conflict`）验证向编号 2 追加与
  编号 1 同名的章节互不影响。

## 4. 章节名的处理规则

对应 `core.py:111-149` 的 `append_chapter`：

1. **只去首尾空白**：`name = (name or "").strip()`（`core.py:125`）。
   内部空白与大小写**原样保留**。实测 `--chapter " 回顾 "` 存为 `回顾`；
   测试 `tests/test_append_chapter.py:183-189` 用 `"  阶段  复习  "` 验证
   存为 `阶段  复习`（内部双空格保留）。
2. **重名比较仅限同一课程且区分大小写**：先把该课程已有章节名按位置取出
   （`core.py:134-141`），再用 `name in existing` 做普通 Python 字符串比较
   （`core.py:142`）——比较对象是**去首尾空白后**的名字，大小写敏感，
   且只查当前 `course_id` 的行。因此：
   - `" 准备 "` 与已有 `准备` 视为重名（测试 `:254-262`）；
   - 大小写不同的名字不冲突，如实测场景对应的测试 `:264-270`：已有
     `Reading` 时可再追加 `reading`；
   - 其他课程的同名章节不参与比较（测试 `:211-218`）。
3. **追加位置**：新章节的 `position` 取追加前已有章节数（`core.py:144`），
   即排在原列表最后；连续追加按追加顺序依次后移（测试 `:191-201`
   `test_append_successively_appends_in_order`）。
4. **不变量**：课程标题、编号与此前的章节名称、顺序均不变——函数只执行
   一次章节 INSERT，不触碰 `courses` 表与既有章节行。

## 5. 失败示例

以下每条均给出输入、标准错误与退出码，均为本次实测（在已登记「入门培训」
两章的临时库上执行，命令前缀 `python -m course_progress --db <库文件>` 省略）。
所有失败情形共同的可观察结果：

- **标准输出为空**；标准错误只有一行中文消息，**不显示异常堆栈**
  （`main` 对 `ValidationError` 的捕获在 `__main__.py:123-125`，编号与
  存在性错误分别在 `:105-108`、`:126-128`；测试
  `tests/test_append_chapter.py:137-145` 逐条断言空 stdout、唯一消息、
  无 `Traceback`）；
- **原课程详情与概览保持不变**（测试 `:147-151` 的 `assert_state_unchanged`
  在每个失败用例后校验两门课程详情与概览）。

### 5.1 编号不是正整数：退出码 2

| 输入 | 标准错误 | 退出码 |
| --- | --- | --- |
| `append-chapter 0 --chapter "回顾"` | `课程编号必须为正整数` | 2 |
| `append-chapter -3 --chapter "回顾"` | `课程编号必须为正整数` | 2 |
| `append-chapter abc --chapter "回顾"` | `课程编号必须为正整数` | 2 |

源码依据：`parse_positive_int`（`__main__.py:69-75`）先 `strip()`，再用正则
`[+-]?\d+` 做 `fullmatch`，仅接受大于 0 的整数；失败时
`__main__.py:105-108` 输出 `ERR_BAD_ID`（`core.py:9`）并返回 2。
对应测试 `tests/test_append_chapter.py:220-228`。

### 5.2 正整数编号但课程不存在：退出码 1

| 输入 | 标准错误 | 退出码 |
| --- | --- | --- |
| `append-chapter 42 --chapter "回顾"` | `课程不存在` | 1 |
| `append-chapter 9223372036854775808 --chapter "回顾"` | `课程不存在` | 1 |

源码依据：`append_chapter` 先做 int64 范围检查（`core.py:123-124`，
`9223372036854775808` = 2⁶³ 超出 SQLite 64 位有符号整数上限，直接返回
`None`），再查 `courses` 表（`core.py:127-131`），查无此行同样返回 `None`；
CLI 在 `__main__.py:126-128` 输出 `ERR_NOT_FOUND`（`core.py:8`）并返回 1。
对应测试 `tests/test_append_chapter.py:230-238`。

### 5.3 课程存在但章节名为空：退出码 1

| 输入 | 标准错误 | 退出码 |
| --- | --- | --- |
| `append-chapter 1`（省略 `--chapter`） | `章节不能为空` | 1 |
| `append-chapter 1 --chapter "   "`（只有空白） | `章节不能为空` | 1 |

源码依据：`--chapter` 不是必填（`__main__.py:58`），省略时 `args.chapter`
为 `None`，经 `core.py:125` 的 `(name or "").strip()` 归一为空串；课程存在
而名称为空时在 `core.py:132-133` 抛出
`ValidationError(ERR_EMPTY_CHAPTER)`（常量见 `core.py:6`）。
对应测试 `tests/test_append_chapter.py:240-252`。

### 5.4 去首尾空白后与已有章节重名：退出码 1

| 输入 | 标准错误 | 退出码 |
| --- | --- | --- |
| `append-chapter 1 --chapter "准备"` | `章节名重复` | 1 |
| `append-chapter 1 --chapter " 准备 "` | `章节名重复` | 1 |

源码依据：`core.py:134-143`，按第 4 节第 2 条的规则比较，命中即抛
`ValidationError(ERR_DUP_CHAPTER)`（常量见 `core.py:7`）。
对应测试 `tests/test_append_chapter.py:254-262`。

### 5.5 多问题并存时只报首个错误

判定顺序固定为 **编号格式 → 课程存在性 → 章节非空 → 重名**，靠前者胜出：

- 编号格式在 CLI 层最先判定（`__main__.py:105-108` 先于 `:120` 的分派）：
  实测 `append-chapter abc`（同时缺 `--chapter`）只报
  `课程编号必须为正整数`，退出码 2。测试 `:286-297`。
- 课程存在性在 `append_chapter` 内先于章节检查（`core.py:127-131` 先于
  `:132-143`）：实测 `append-chapter 42`（缺 `--chapter`）只报
  `课程不存在`，退出码 1。测试 `:299-315` 还覆盖未知编号配空白/重复章节名。
- 章节非空先于重名（`core.py:132-133` 先于 `:134-143`）：空白名只报
  `章节不能为空`，不进入重名判定。测试 `:317-323`。

### 5.6 成功后重复提交同一名称

追加「回顾」成功后，再执行 `append-chapter 1 --chapter "回顾"`：实测标准错误
`章节名重复`，退出码 1，标准输出为空，**不会再增加章节**——首次追加的结果
保持为 `["准备", "学习", "回顾"]`。原因即第 4 节：此时「回顾」已是该课程
已有章节，命中重名检查。对应测试
`tests/test_append_chapter.py:272-284`
（`test_repeated_submission_fails_as_duplicate`）。

### 5.7 「不新增数据」的准确边界

- **数据行层面**：上述所有失败都在任何 INSERT 之前返回或抛错
  （`core.py:123-143` 全部先于 `:145-148` 的写入），因此不新增任何
  `courses`/`chapters` 行；5.1–5.6 的每个失败用例后测试都重新校验详情与概览。
- **文件/表结构层面**：`connect()` 先于一切校验执行（`__main__.py:85` 在
  `:105` 与 `:120` 之前），因此对一个**全新路径**执行失败的追加（如实测的
  `append-chapter 9 --chapter "x"` 报「课程不存在」）仍会留下已建表的空
  数据库文件——实测该文件含 `courses`、`chapters`、`sqlite_sequence` 三张表，
  两表均为 0 行。即「不新增数据行」不等于「不创建数据库文件和表」；
  对已存在的库文件执行失败追加则无此区别。
