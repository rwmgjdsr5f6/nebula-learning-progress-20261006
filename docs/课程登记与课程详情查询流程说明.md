# 课程登记与课程详情查询流程说明

> 范围：仅覆盖「课程标题 + 有序章节 + 本地保存」这条路径——课程登记（`add-course`）、
> 课程编号的取得、课程详情查询（`get-course`）。不涉及学员、练习、结业等流程。
>
> 本说明只陈述能由仓库中实际存在的公开文档、入口和源码核对的行为。核对方式：
>
> - 源码版本：git 提交 `e3690d4`（工作区干净）；
> - 实测环境：Python 3.14.4 / Linux。README 命令写作 `python`，本机 `python` 不存在，
>   实测以等价的 `python3 -m course_progress ...` 运行；除解释器名外命令形式与 README 完全一致；
> - 仓库自带测试 `python3 -m unittest tests.test_cli_flow` 共 10 个用例，核对时全部通过。

## 2. 端到端路径总览

```
命令行参数
  └─ argparse 解析（build_parser）              __main__.py:22-50
       └─ 检查 --db 是否提供                      __main__.py:64-67
            └─ connect(db_path)：打开/创建 SQLite 并建表   core.py:29-33
                 └─ add_course(conn, title, chapters)     core.py:36-57
                      ├─ 去首尾空白
                      ├─ 保存前校验（标题→空章节→重复章节）
                      └─ 一个事务内写 courses 与 chapters
                 └─ stdout 输出 {"course_id": N}           __main__.py:80
```

查询走同一入口与同一个 `--db` 文件：`get-course` → 编号解析（`parse_positive_int`）→
`get_course` 读 `courses` 与 `chapters` → stdout 输出一行 JSON。

## 3. 保存位置如何决定、表结构、关闭后能否取回

### 3.1 保存位置由调用方通过 `--db` 显式指定

- 没有默认数据库路径，也没有环境变量、用户主目录等自动定位逻辑：对全仓库检索
  `getenv`/`environ`/`expanduser`/`Path.home` 均无匹配。存储位置唯一来源是 `--db` 参数
  （`course_progress/__main__.py:64`，`db_path = getattr(args, "db", None)`）。
- 不提供 `--db` 时直接报错退出，不接触任何数据库：
  stderr `必须通过 --db 指定数据库文件`，退出码 **2**（`__main__.py:65-67`）。
- `--db` 写在子命令前或后均可（`__main__.py:27` 与各子命令的 `--db` 定义
  `__main__.py:31,41,48-49`；测试 `tests/test_cli_flow.py:110-127` 覆盖）。
- 父目录必须预先存在；数据库文件不存在时自动创建（`core.py:29-33` 的
  `sqlite3.connect(db_path)` + 建表脚本；`README.md:7` 同样如此说明）。父目录不存在时
  实测：stderr `无法打开数据库：unable to open database file`，退出码 1（`__main__.py:69-72`）。
- 不同 `--db` 文件中的课程彼此独立（`README.md:71`；代码中无任何跨文件共享）。

### 3.2 实际表结构（`course_progress/core.py:11-22` 的 `_SCHEMA`）

```sql
CREATE TABLE IF NOT EXISTS courses (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    title TEXT NOT NULL
);
CREATE TABLE IF NOT EXISTS chapters (
    course_id INTEGER NOT NULL REFERENCES courses (id),
    position INTEGER NOT NULL,
    name TEXT NOT NULL,
    PRIMARY KEY (course_id, position)
);
```

- `courses.id` 为 `INTEGER PRIMARY KEY AUTOINCREMENT`，编号由 SQLite 产生；AUTOINCREMENT
  会额外维护 `sqlite_sequence` 表（实测新建库中可见 `courses`、`chapters`、`sqlite_sequence`
  三张表）。
- 课程与章节通过 `chapters.course_id` 关联；同一课程内的章节顺序由 `chapters.position`
  表达，联合主键 `(course_id, position)` 保证同一课程不出现两个相同位置。
- 两点如实注明的实现细节：
  - `position` 从 **0** 开始计数（写入用 `enumerate(names)`，`core.py:55`）。
  - 表结构声明了 `REFERENCES courses (id)`，但全仓库没有 `PRAGMA foreign_keys=ON`，
    而 Python `sqlite3` 默认不启用外键约束，因此该外键当前只是 schema 声明、未被强制；
    目前也不存在任何删除课程的代码路径，故此点当前没有可观察后果。

### 3.3 关闭程序后重新打开同一存储位置可以取回原课程

- 数据写入普通 SQLite 文件并提交（`add_course` 用 `with conn:` 事务，`core.py:50-56`）。
- 测试 `tests/test_cli_flow.py:94-108`（`test_add_then_get_preserves_order_across_processes`）
  用两次独立子进程验证：第一次进程登记退出后，第二次进程对**同一 `--db` 路径**查询，
  标题、章节数量与顺序完全一致。
- 实测同样确认：登记退出后另起调用 `get-course` 可取回全部内容，直接打开该 `.db`
  文件可见 `courses` 与 `chapters` 中的落盘行。
- 结论：只要重新打开时传入同一个 `--db` 路径（且文件未被外部删除/移动），即可取回原课程；
  章节顺序由查询中的 `ORDER BY position` 决定（见第 6 节），不依赖插入后的偶然行序。

## 4. 一次登记请求从输入到结果

对应函数：`course_progress/core.py:36-57` 的 `add_course(conn, title, chapters)`；
CLI 调用点在 `course_progress/__main__.py:74-81`。

1. **参数接收（CLI 层，`build_parser`，`__main__.py:30-38`）**
   - `--title`：必填字符串；缺失时由 argparse 报 usage 错误、退出码 2（实测）。
   - `--chapter`：`action="append"`、`default=[]`，可重复；argparse 按命令行出现顺序
     收集成列表，注释明确「出现顺序即章节顺序」（`__main__.py:33-38`）。完全不提供时
     为 Python 空列表 `[]`。
2. **打开存储（先于校验）**：`main` 在调用 `add_course` 之前先执行
   `connect(db_path)`（`__main__.py:69` 与 `:76`）。即任何校验发生之前，数据库文件与
   两张表就已经创建（若原本不存在）。这点与失败后是否「留下数据」相关，见第 7.4 节。
3. **去除首尾空白**：`title = title.strip()`；每个章节名同样 `strip()`
   （`core.py:42-43`）。保存进数据库的是去除空白后的值。
4. **保存之前的检查（全部在任何 INSERT 之前，`core.py:44-49`）**，按固定顺序，
   失败即抛 `ValidationError`（定义于 `core.py:25-26`），只报首个错误：

   | 顺序 | 检查 | 代码位置 | 触发条件 | 异常/消息 |
   | --- | --- | --- | --- | --- |
   | 1 | 标题非空 | `core.py:44-45` | `strip()` 后标题为空 | `ValidationError("课程标题不能为空")` |
   | 2 | 章节非空 | `core.py:46-47` | 未提供任何 `--chapter`（列表为空），或任一章节名 `strip()` 后为空 | `ValidationError("章节不能为空")` |
   | 3 | 章节名不重复 | `core.py:48-49` | `len(set(names)) != len(names)`，即对**去空白后**的名字做**大小写敏感**比较存在重复 | `ValidationError("章节名重复")` |

   - 大小写敏感由普通 Python 字符串集合比较直接保证：实测 `Aa` 与 `aa` 可同时登记成功；
     `README.md:60` 也明确「去首尾空白后按大小写敏感比较」。
   - 多问题并存时的优先级（标题 → 空章节 → 重复章节）与 `README.md:62` 一致，
     并有测试 `tests/test_cli_flow.py:175-194`。
5. **课程与章节在同一事务内写入并关联（`core.py:50-57`）**
   - `INSERT INTO courses (title) VALUES (?)`，随后用 `cursor.lastrowid` 取得新课程编号
     `course_id`（`core.py:51-52`）。
   - `executemany` 一次性插入章节，位置来自 `enumerate(names)`：
     `(course_id, 0, 第一章), (course_id, 1, 第二章), …`（`core.py:53-56`）。
     课程与章节即通过该 `course_id` 值关联。
   - 两步位于同一个 `with conn:` 事务中：若章节插入阶段出错，课程行随之回滚，
     不会出现「有课程、无章节」的半截数据。
6. **输出**：成功返回 `course_id`；CLI 在 stdout 打印一行 JSON
   `{"course_id": <N>}`（`ensure_ascii=False`，中文不转义），退出码 0
   （`__main__.py:80-81`）。校验异常在 `__main__.py:77-79` 捕获：消息写 stderr、
   stdout 为空、退出码 1。

### 编号如何产生与取得

- 编号不是用户指定的，而是 SQLite 对 `courses.id`（AUTOINCREMENT）自动产生，
- 全新数据库的第一门课编号为 1，之后单调递增；实测连续登记得到 1、2、3
  （`README.md:22` 同样如此说明）。
- 取得方式：读取 `add-course` 成功时 stdout 的 JSON 字段 `course_id`，把它作为后续
  `get-course` 的位置参数。没有单独的「取号」动作。
- 辅助途径：`list-courses` 可列出全部课程的 `course_id`（按编号升序），
  README `README.md:38-50` 有记载；本说明主线不依赖它。

## 5. 固定示例：入门培训（准备 / 学习 / 回顾）

以下命令形式与 README 记载的公开入口一致（`README.md:11-34`）。在仓库根目录执行，
使用一个全新的数据库文件（父目录需已存在）：

### 5.1 准备

```bash
mkdir -p data
```

### 5.2 登记输入

```bash
python -m course_progress --db data/course.db add-course \
    --title "入门培训" \
    --chapter "准备" --chapter "学习" --chapter "回顾"
```

### 5.3 课程编号的取得

stdout（退出码 0）：

```json
{"course_id": 1}
```

- 这里的 `1` 仅因为这是**全新空库**的第一门课；一般流程不应预设具体数字，
  而是解析该 JSON、取 `course_id` 字段值用于下一步。
- 实测落盘内容（直接读取 SQLite 文件）：
  `courses` = `(1, '入门培训')`；
  `chapters` = `(1, 0, '准备'), (1, 1, '学习'), (1, 2, '回顾')`。

### 5.4 详情查询（用上一步的登记结果）

```bash
python -m course_progress --db data/course.db get-course 1
```

### 5.5 实际可确认的返回内容

stdout（退出码 0）：

```json
{"course_id": 1, "title": "入门培训", "chapters": ["准备", "学习", "回顾"]}
```

- 字段为 `course_id`、`title`、`chapters`（由 `core.py:95` 的返回字典决定）。
- `chapters` 顺序为 **准备 → 学习 → 回顾**，与登记时 `--chapter` 的出现顺序一致。
  决定机制：写入时位置 0/1/2（`core.py:53-56`），查询时
  `SELECT name FROM chapters WHERE course_id = ? ORDER BY position`
  （`core.py:88-94`）——顺序由 `position` 列的升序决定，而非章节名字典序或行的物理顺序。
- 关闭进程后用同一 `--db data/course.db` 再次查询，输出与上面完全相同（跨进程持久化，
  见第 3.3 节及 `tests/test_cli_flow.py:101-108`）。

## 6. 详情查询流程

对应 `course_progress/core.py:81-95` 的 `get_course` 与 `__main__.py:89-98` 的分派逻辑：

1. `parse_positive_int(raw)`（`__main__.py:53-59`）解析编号：先 `strip()`，再用正则
   `_ID_PATTERN = re.compile(r"[+-]?\d+")` 做 `fullmatch`（`__main__.py:19,56`），
   然后 `int(text)`，仅当结果 `> 0` 才接受，否则返回 `None`。
2. 解析失败：stderr `课程编号必须为正整数`，退出码 **2**（`__main__.py:89-92`；
   `README.md:69`）。
3. 解析成功后 `get_course`：先 `SELECT title FROM courses WHERE id = ?`，查不到返回
   `None`（`core.py:83-87`）→ CLI 输出 stderr `课程不存在`、退出码 **1**
   （`__main__.py:93-96`；`README.md:68`）。
4. 查到则再按 `ORDER BY position` 取章节名列表（`core.py:88-94`），返回
   `{"course_id": ..., "title": ..., "chapters": [...]}`，CLI 以一行 JSON 打到 stdout，
   退出码 0（`__main__.py:97-98`）。

## 7. 失败情形与失败后的数据残留

### 7.1 空标题

- 检查位置：`add_course` 中保存前的第 1 道检查，`course_progress/core.py:44-45`。
- 异常类型：`ValidationError`（`core.py:25-26`），消息常量 `ERR_EMPTY_TITLE`
  （`core.py:5`）；CLI 捕获处 `__main__.py:77-79`。
- 命令行可观察结果（实测 `--title "   "`）：stderr `课程标题不能为空`，
  stdout 为空，退出码 **1**。与 `README.md:58` 一致。
- 是否留下课程数据：**不留下任何 courses/chapters 行**。检查位于任何 INSERT 之前
  （对比第 4 节步骤 2–5 的先后）。测试 `tests/test_cli_flow.py:130-140` 在失败后用
  `list-courses` 验证返回 `{"courses": []}`，再登记仍得到编号 1。

### 7.2 同一课程内重复章节名

- 检查位置：`add_course` 中保存前的第 3 道检查，`course_progress/core.py:48-49`
  （`set` 长度比较，针对 `strip()` 后的名字、大小写敏感）。
- 异常类型：`ValidationError`，消息常量 `ERR_DUP_CHAPTER`（`core.py:7`）。
- 命令行可观察结果（实测 `--chapter "准备" --chapter "准备"`）：
  stderr `章节名重复`，stdout 为空，退出码 **1**。与 `README.md:60` 一致。
  测试 `tests/test_cli_flow.py:161-173`（含 `" 安装环境 "` 与 `"安装环境"` 被视为重复）。
- 是否留下课程数据：**不留下任何行**，理由同 7.1；失败后库为空、再登记编号仍为 1
  （`tests/test_cli_flow.py:161-173` 复用同一空库校验）。
- 边界：重复比较仅限同一次登记内部；不同课程之间允许同名章节（代码按 `course_id`
  过滤，联合主键也以 `course_id` 分隔）。课程标题也允许重复——实测同名「入门培训」
  可分别登记为不同编号；`README.md:50` 明确「同标题的课程分别列出」。

### 7.3 未知课程编号

- 检查位置：`get_course` 查 `courses` 无此行返回 `None`（`core.py:83-87`），
  CLI 判空处在 `__main__.py:93-96`。
- 命令行可观察结果（实测全新库 `get-course 42`）：stderr `课程不存在`，
  stdout 为空，退出码 **1**。与 `README.md:68` 一致；
  测试 `tests/test_cli_flow.py:198-200`。
- 是否留下课程数据：查询不执行任何写入，不新增课程或章节。

### 7.4 「不留下记录」的准确边界（实测澄清）

`README.md:54` 表述为登记失败时「数据库不留下任何记录」。核对结论：

- **记录（数据行）层面属实**：实测两次登记失败后直接读取该库，
  `SELECT * FROM courses` 与 `SELECT * FROM chapters` 均为空；上述测试也如此断言。
- **文件/表结构层面**：因为 `connect()` 先于校验执行（第 4 节步骤 2），失败时
  数据库文件与 `courses`、`chapters`、`sqlite_sequence` 表**已经被创建**，只是其中
  0 行。对全新路径执行一次失败的 `get-course 42` 同样会留下已建表的空库文件（实测）。
  即「不留下任何记录」不等于「不创建数据库文件和表」。README 未明确写出这一点，
  代码依据为 `__main__.py:69` 先于 `:76`，以及 `core.py:31-32` 的建表 DDL。

## 8. 文档与代码的核对结论

- 本范围内未发现 README 与源码**相互矛盾**的条目：登记输出、章节顺序、三类登记错误
   的消息/优先级/退出码、两类查询错误、空库 `list-courses` 行为、自动建库与父目录
   前提、跨进程持久化、同标题课程分别列出，均与代码和实测一致（对应行见第 4、6、7 节）。
- README **未记载**、但由源码和实测确认的行为集中在第 7.4 与 7.5：失败调用仍会创建
  空库与表、缺 `--db` 的退出码 2、`+3`/前导零/外围空白被接受、超大整数编号触发未捕获
  `OverflowError`、argparse 层缺参退出码 2。这些按「代码实际行为」记录，未替 README
