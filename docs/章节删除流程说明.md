## 2. 调用形式与数据库定位

与登记、查询、追加完全相同的约定（README 对整体 CLI 有记载，源码同样适用）：

- 通过 `python -m course_progress` 调用，每次用 `--db` 指定数据库文件。
- **父目录必须预先存在**；数据库文件不存在时会自动建库建表
  （`core.py:37-41` 的 `sqlite3.connect(db_path)` + `_SCHEMA` 建表脚本）。
- **`--db` 写在子命令前后均可**：全局 `--db` 定义于 `build_parser`，
  `remove-chapter` 子命令级的 `--db` 定义于 `__main__.py:76-78`；测试
  `test_db_option_after_subcommand` 覆盖子命令后的写法，第 3 节的实测也验证了
  两种形式。
- 子命令语法（`__main__.py:73-80`）：

  ```
  remove-chapter <course_id> [--chapter <章节名>]
  ```

  `course_id` 为位置参数；`--chapter` 为可选标志（省略时按空章节处理，见第 5 节）。

## 3. 成功示例：从「入门培训」删除「学习」

前提：编号 1 的课程「入门培训」有三章「准备」「学习」「回顾」；另有编号 2 的
课程「复习培训」仅含「学习」一章（均由 `add-course` 登记）。以下命令在仓库根
目录执行。

### 3.1 删除章节

```bash
python -m course_progress --db demo.db remove-chapter 1 --chapter " 学习 "
```

注意传入的章节名首尾各带一个空格。实测结果：

- 标准输出**仅一行** JSON，退出码 **0**，标准错误为空：

  ```json
  {"course_id": 1, "title": "入门培训", "chapters": ["准备", "回顾"]}
  ```

  输出结构与 `get-course` 完全相同（`course_id`、`title`、`chapters`）；该返回值
  在 `core.py:309` 删除事务提交后由 `get_course(conn, course_id)` 组装得出。
- 中间章「学习」被删除，剩余「准备」「回顾」的**名称与相对顺序不变**。

### 3.2 重新打开同一数据库

```bash
python -m course_progress --db demo.db get-course 1
```

实测标准输出（退出码 0，标准错误为空）：

```json
{"course_id": 1, "title": "入门培训", "chapters": ["准备", "回顾"]}
```

- 删除在 `with conn:` 事务中提交（DELETE 与 UPDATE 分别在 `core.py:299-302`、
  `core.py:304-308`），落盘后跨进程读取结果一致。
- 详情按 `SELECT name FROM chapters WHERE course_id = ? ORDER BY position`
  取回，顺序由 `position` 列决定，不依赖行的物理顺序。
- 概览实测：

  ```json
  {"courses": [{"course_id": 1, "title": "入门培训", "chapter_count": 2}, {"course_id": 2, "title": "复习培训", "chapter_count": 1}]}
  ```

  编号 1 的 `chapter_count` 由 3 变为 2，编号 2 仍为 1。
- 编号 2 详情实测仍为
  `{"course_id": 2, "title": "复习培训", "chapters": ["学习"]}`——其他课程的同名
  章节不受影响。

### 3.3 删除后再追加

删除中间章后执行 `append-chapter 1 --chapter "测验"`，实测编号 1 详情为

```json
{"course_id": 1, "title": "入门培训", "chapters": ["准备", "回顾", "测验"]}
```

追加的新章节排在剩余最后一章「回顾」之后。原因：删除时被删位置之后的章节统一
前移一位（`core.py:303-308`），剩余 `position` 重新压紧为从 0 起的连续编号；
追加取「现有章节数」作为新位置，因此新章位于 2，即列表末尾。对应测试
`test_append_after_remove_goes_after_last_remaining_chapter`。

## 4. 章节名的处理与删除规则

对应 `core.py:260-309` 的 `remove_chapter`：

1. **只去首尾空白**：`chapter = (chapter or "").strip()`（`core.py:276`）。
   内部空白与大小写**原样保留**。实测 `--chapter " 学习 "` 定位到「学习」；
   测试 `test_remove_preserves_inner_spaces_and_is_case_sensitive` 用
   `"  阶段  复习  "` 验证可命中名为 `阶段  复习`（内部双空格）的章节。
2. **在本课程内按大小写敏感精确匹配**：先把该课程章节按位置取出
   （`core.py:285-292`），再以 `{名称: 位置}` 字典做普通 Python 字符串键查找
   （`core.py:293-295`）——比较对象是**去首尾空白后**的名字，大小写敏感，且只查
   当前 `course_id` 的行。因此：
   - 其他课程的同名章节不算命中（编号 1 删「学习」不影响编号 2 的「学习」，测试
     `test_other_courses_same_named_chapter_is_not_a_match`）；
   - 大小写不同不视为同一章节（`reading` 不命中 `Reading`，测试
     `test_remove_preserves_inner_spaces_and_is_case_sensitive`）。
3. **至少保留一章**：命中章节且其为该课程唯一章节时（`core.py:296-297`，
   `len(existing) == 1`），抛出 `ValidationError(ERR_LAST_CHAPTER)`，不执行删除。
4. **删除即压紧位置**：先按目标 `position` 删除该行（`core.py:299-302`），再把
   其后所有章节的 `position` 减 1（`core.py:304-308`）。剩余章节相对顺序不变，
   且位置连续，保证后续追加落在末尾。
5. **不变量**：课程编号、标题、其他课程均不变；函数只触碰目标 `course_id` 的
   `chapters` 行，不修改 `courses` 表。

## 5. 失败示例

以下给出输入、标准错误与退出码，均为实测/测试覆盖。所有失败情形共同的可观察
结果：

- **标准输出为空**；标准错误只有一行中文消息，**不显示异常堆栈**
  （`main` 对 `ValidationError` 的捕获在 `__main__.py:181-183`，编号与存在性
  错误分别在 `:139-142`、`:184-186`；测试统一断言空 stdout、唯一消息、无
  `Traceback`）；
- **原课程详情与概览保持不变**：全部校验都在 DELETE/UPDATE
  （`core.py:299-308`）之前完成，失败用例后测试重新校验两门课程详情与概览。

### 5.1 编号不是正整数：退出码 2

| 输入 | 标准错误 | 退出码 |
| --- | --- | --- |
| `remove-chapter 0 --chapter "学习"` | `课程编号必须为正整数` | 2 |
| `remove-chapter -3 --chapter "学习"` | `课程编号必须为正整数` | 2 |
| `remove-chapter abc --chapter "学习"` | `课程编号必须为正整数` | 2 |

源码依据：`parse_positive_int`（`__main__.py:103-109`）先 `strip()`，再用正则
`[+-]?\d+` 做 `fullmatch`，仅接受大于 0 的整数；失败时
`__main__.py:139-142` 输出 `ERR_BAD_ID` 并返回 2，先于一切子命令分派。
对应测试 `test_bad_course_id_format`。

### 5.2 正整数编号但课程不存在：退出码 1

| 输入 | 标准错误 | 退出码 |
| --- | --- | --- |
| `remove-chapter 42 --chapter "学习"` | `课程不存在` | 1 |
| `remove-chapter 9223372036854775808 --chapter "学习"` | `课程不存在` | 1 |

源码依据：`remove_chapter` 先做 int64 范围检查（`core.py:274-275`，
`9223372036854775808` = 2⁶³ 超出 SQLite 64 位有符号整数上限，直接返回
`None`），再查 `courses` 表（`core.py:278-282`），查无此行同样返回 `None`；
CLI 在 `__main__.py:184-186` 输出 `ERR_NOT_FOUND` 并返回 1。
对应测试 `test_unknown_course_id`。

### 5.3 课程存在但章节名为空：退出码 1

| 输入 | 标准错误 | 退出码 |
| --- | --- | --- |
| `remove-chapter 1`（省略 `--chapter`） | `章节不能为空` | 1 |
| `remove-chapter 1 --chapter "   "`（只有空白） | `章节不能为空` | 1 |

源码依据：`--chapter` 不是必填（`__main__.py:80`），省略时 `args.chapter`
为 `None`，经 `core.py:276` 的 `(chapter or "").strip()` 归一为空串；课程存在
而名称为空时在 `core.py:283-284` 抛出
`ValidationError(ERR_EMPTY_CHAPTER)`。对应测试
`test_missing_chapter_option`、`test_blank_chapter_for_existing_course`。

### 5.4 名称非空但章节不存在：退出码 1

| 输入 | 标准错误 | 退出码 |
| --- | --- | --- |
| `remove-chapter 1 --chapter "不存在的章节"` | `章节不存在` | 1 |
| `remove-chapter 1 --chapter "learning"`（库中为 `Learning`） | `章节不存在` | 1 |

源码依据：`core.py:293-295` 在本课程章节中做大小写敏感精确查找，未命中即抛
`ValidationError(ERR_CHAPTER_NOT_FOUND)`。删除成功后再次提交同名删除同样落到
此项（见 5.6）。对应测试 `test_unknown_chapter`、
`test_repeated_remove_same_name_fails_as_not_found`。

### 5.5 删除唯一章节：退出码 1

| 输入 | 标准错误 | 退出码 |
| --- | --- | --- |
| `remove-chapter 2 --chapter "学习"`（课程 2 仅此一章） | `课程至少保留一个章节` | 1 |

源码依据：命中章节且 `len(existing) == 1` 时在 `core.py:296-297` 抛出
`ValidationError(ERR_LAST_CHAPTER)`（常量 `core.py:10`），不执行任何写入，
该章保留。对应测试 `test_remove_only_chapter_rejected_and_kept`。

### 5.6 成功后重复提交同一名称

删除编号 1 的「学习」成功后，再执行 `remove-chapter 1 --chapter "学习"`：实测
标准错误 `章节不存在`，退出码 1，标准输出为空，章节列表保持
`["准备", "回顾"]`。此时「学习」已不在该课程中，命中 5.4 的章节存在性判定，而
非 5.5 的唯一章节保护。对应测试
`test_repeated_remove_same_name_fails_as_not_found`。

### 5.7 多问题并存时只报首个错误

判定顺序固定为 **编号格式 → 课程存在性 → 名称非空 → 章节存在性 → 是否为唯一
章节**，靠前者胜出：

- 编号格式在 CLI 层最先判定（`__main__.py:139-142` 先于 `:178` 的分派）：
  `remove-chapter abc`（同时缺 `--chapter`）只报 `课程编号必须为正整数`，
  退出码 2（`test_bad_id_reported_before_other_errors`）。
- 课程存在性在 `remove_chapter` 内先于章节检查（`core.py:278-282` 先于
  `:283-297`）：`remove-chapter 42`（缺 `--chapter`）只报 `课程不存在`，
  退出码 1（`test_unknown_id_reported_before_chapter_errors`）。
- 名称非空先于章节存在性与唯一章节判定（`core.py:283-284`）：对仅有一章的
  课程 2 传空白名，只报 `章节不能为空`
  （`test_empty_chapter_reported_before_unknown_and_last`）。
- 章节存在性先于唯一章节判定（`core.py:294-295` 先于 `:296-297`）：对仅有
  一章的课程 2 传一个未知名称，只报 `章节不存在`，不报「至少保留一个章节」
  （`test_unknown_chapter_reported_before_last_chapter_guard`）。

### 5.8 「不修改数据」的准确边界

- **数据行层面**：5.1–5.6 的所有失败都在任何 DELETE/UPDATE 之前返回或抛错
  （`core.py:274-297` 全部先于 `:299-308` 的写入），因此不改动任何
  `courses`/`chapters` 行；每个失败用例后测试都重新校验详情与概览。
- **文件/表结构层面**：`connect()` 先于一切校验执行，因此对一个**全新路径**
  执行失败的删除仍会留下已建表的空数据库文件，与追加等既有子命令一致；对已
  存在的库文件执行失败删除则无此区别。
