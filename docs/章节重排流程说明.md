## 3. 调用形式与数据库定位

- 通过 `python -m course_progress` 调用，用 `--db` 指定数据库文件；无默认库
  路径。子命令语法（`__main__.py:90-100`）：

  ```
  reorder-chapters <course_id> --chapter <名称> [--chapter <名称> …]
  ```

  `course_id` 为位置参数；`--chapter` 使用 `action="append"`、`default=[]`，
  按命令行出现顺序收集为列表，帮助文本明确「出现顺序即新的章节顺序，须与现有
  章节一一对应」（`__main__.py:95-100`）。完全不提供时为 Python 空列表。
- **`--db` 写在子命令前或后均可**：全局 `--db` 定义于 `__main__.py:49`，
  子命令级 `--db` 定义于 `__main__.py:93`。测试
  `tests/test_reorder_chapters.py:215-220`（`test_db_option_after_subcommand`）
  覆盖子命令后的写法。
- **父目录必须预先存在**；文件不存在时 `connect` 自动建库建表
  （`core.py:86-90`），父目录不存在时 stderr 为
  `无法打开数据库：…`、退出码 1（`__main__.py:223-227`）。
- 表结构中章节以 `(course_id, position)` 为联合主键、`position` 从 0 开始
  （`core.py:23-28`），这是第 4.4 节「先平移再落位」写法的由来。

## 4. 固定样例：入门培训（准备 / 学习 / 回顾 → 回顾 / 准备 / 学习）

在仓库根目录执行，使用根目录下的 `sample.db`（父目录即当前目录，已存在）。
要使登记出的课程编号恰为 1，`sample.db` 必须是**全新数据库**：若该文件已存在
（仓库随附的 `sample.db` 装有其他流程文档的样例数据），请先删除它或换用其他
路径。本文实测即先删除、再由登记命令重建；实测结束后已把随附文件还原。

### 4.1 登记课程（现有登记入口）

```bash
python -m course_progress --db sample.db add-course --title "入门培训" --chapter "准备" --chapter "学习" --chapter "回顾"
```

实测标准输出（退出码 0，标准错误为空）：

```json
{"course_id": 1}
```

全新空库的第一门课编号为 1，章节按 `--chapter` 出现顺序保存为
准备、学习、回顾（登记逻辑见 `core.py:93-114` 的 `add_course`）。

### 4.2 重排章节

```bash
python -m course_progress --db sample.db reorder-chapters 1 --chapter 回顾 --chapter 准备 --chapter 学习
```

实测：退出码 **0**，**标准错误为空**，标准输出为**一行** JSON：

```json
{"course_id": 1, "title": "入门培训", "chapters": ["回顾", "准备", "学习"]}
```

- 输出由 `json.dumps(..., ensure_ascii=False)` 产生（`__main__.py:380`），
  中文不转义；冒号与逗号后带默认空格。测试按解析后的 JSON 比较，不限定空格
  （`tests/test_reorder_chapters.py:130-141`）。
- 该 JSON 与 `get-course` 的输出**同结构、同来源**：`reorder_chapters` 末尾
  直接返回 `get_course(conn, course_id)`（`core.py:310`），字段为
  `course_id`、`title`、`chapters`（`core.py:400`）。

### 4.3 随后查询详情（重新打开同一文件）

```bash
python -m course_progress --db sample.db get-course 1
```

实测标准输出（退出码 0，标准错误为空）：

```json
{"course_id": 1, "title": "入门培训", "chapters": ["回顾", "准备", "学习"]}
```

每条 CLI 命令都是独立进程，本次查询即重排进程退出后**重新打开同一 `sample.db`**
的结果；实测紧接着再次执行 `get-course 1`，输出完全相同。持久化的源码依据：
重排的 UPDATE 在 `with conn:` 事务中提交（`core.py:279,300-309`），详情查询按
`SELECT name FROM chapters WHERE course_id = ? ORDER BY position`
（`core.py:393-399`）取回，顺序由 `position` 列决定，与行的物理顺序无关。
对应测试 `tests/test_reorder_chapters.py:159-174`
（`test_reorder_persists_across_processes`），它在独立子进程间验证新顺序落库。

### 4.4 保存时章节如何匹配与落位（源码推导）

1. 每个传入名称先 `strip()`（`core.py:278`），再做校验与匹配；内部空白与
   大小写保留，**保存的章节名本身不变**——重排只改 `position`，不写 `name`
   列。实测传入 `回顾` 落位到 0，库里名字仍是登记时的 `回顾`；测试
   `tests/test_reorder_chapters.py:176-192`
   （`test_reorder_strips_surrounding_whitespace`）用带首尾空白与内部双空格的
   名称验证这一点。
2. 匹配是**去首尾空白后、大小写敏感的精确匹配**：校验用 Python 集合比较
   （`core.py:297-298`），落位用参数化 SQL
   `UPDATE chapters SET position = ? WHERE course_id = ? AND name = ?`
   （`core.py:304-309`），两处都按普通字符串精确比较。测试
   `tests/test_reorder_chapters.py:194-208`
   （`test_reorder_matching_is_case_sensitive`）表明 `reading` 不能匹配
   `Reading`，该列表按第 5.5 节报「章节列表与现有章节不一致」。
3. 落位分两步以避开联合主键 `(course_id, position)` 冲突
   （`core.py:299-309`）：先把该课程全部章节的 `position` 整体加 N（N 为现有
   章节数），再按新列表逐章把位置更新为 0、1、…、N-1。成功后 `position`
   仍连续从 0 开始。

### 4.5 不变量与相互隔离

- **课程编号、标题、章节名称与章节数量均不变**：函数只对目标 `course_id` 的
  `chapters` 行做 UPDATE，不触碰 `courses` 表，也不 INSERT/DELETE 章节行
  （`core.py:300-309`）。样例中编号始终是 1、标题始终是「入门培训」、始终是
  同样三章，仅顺序变为回顾、准备、学习。
- **提交原顺序也成功**：实测对样例执行
  `reorder-chapters 1 --chapter 准备 --chapter 学习 --chapter 回顾`，退出码 0、
  标准错误为空，返回的 `chapters` 仍为准备、学习、回顾。重排不是「必须改变
  顺序」的操作，列表一致即通过。对应测试
  `tests/test_reorder_chapters.py:210-213`
  （`test_same_order_submission_succeeds`）。
- **其他课程不受影响**：源码推导，落位 SQL 全部带 `WHERE course_id = ?`；
  回归测试的固定数据包含两门课程（编号 1 三章、编号 2 一章，见
  `tests/test_reorder_chapters.py:23-27,92-101`），重排编号 1 后断言编号 2
  详情与概览章节数逐项不变（`:159-174`、`:215-220`）。本次另在临时库实测：
  两门课程各有一名学员的同一份报名关系时，重排课程 1 前后
  `get-course 2` 与 `list-course-learners 1/2` 的输出完全相同。
- **报名关系不受影响**：`reorder_chapters` 全文不访问 `enrollments` 表
  （`core.py:262-310`），因此报名关系在源码层面不可能被本流程修改；上述
  临时库实测也确认两名册不变。如实注明：CLI 回归测试
  `tests/test_reorder_chapters.py` 的固定数据不含报名记录，报名关系这一条的
  直接依据是源码与本次临时库实测，而非该测试文件。
- 后续追加边界（供衔接核对）：重排后再 `append-chapter`，新章节排在**新顺序**
  的末尾。测试 `tests/test_reorder_chapters.py:222-233`
  （`test_append_after_reorder_goes_to_new_end`）。

## 5. 失败情形（仅覆盖本次重排）

以下结果除固定样例库外，均在含编号 1「入门培训」三章（准备、学习、回顾）的
临时库上实测。所有第 5.3–5.5 节的失败共同表现为：**退出码 1、标准输出为空、
不改变原数据**（失败后实测 `get-course 1` 仍为准备、学习、回顾）。CLI 回归
测试以 `assert_reorder_failure` 统一断言这三点且 stderr 无 `Traceback`
（`tests/test_reorder_chapters.py:143-157`）。

### 5.1 编号不是正整数：退出码 2

| 输入（省略共同的合法章节参数） | 标准错误 | 退出码 |
| --- | --- | --- |
| `reorder-chapters 0 --chapter 准备 --chapter 学习 --chapter 回顾` | `课程编号必须为正整数` | 2 |
| `reorder-chapters -3 --chapter 准备` | `课程编号必须为正整数` | 2 |
| `reorder-chapters abc --chapter 准备` | `课程编号必须为正整数` | 2 |

实测三条均为 stdout 空、退出码 2。源码依据：`parse_positive_int`
（`__main__.py:184-190`）先 `strip()`，再以正则 `[+-]?\d+` 做 `fullmatch`，
`int()` 后仅当 `> 0` 才接受；失败在第 332–335 行打印 `ERR_BAD_ID`
（`core.py:13`）并返回 2。此判定发生在调用 `reorder_chapters` 之前。
对应测试 `tests/test_reorder_chapters.py:235-247`（`test_bad_course_id_format`）。

附注（源码推导）：` 1 `、`007`、`+3` 会被解析器接受为 1、7、3（外围空白、
前导零与可选正号均通过正则与 `int()`），随后按正常编号查课程。

### 5.2 正整数编号但课程不存在：退出码 1

| 输入 | 标准错误 | 退出码 |
| --- | --- | --- |
| `reorder-chapters 42 --chapter 准备 --chapter 学习 --chapter 回顾` | `课程不存在` | 1 |
| `reorder-chapters 9223372036854775808 --chapter 准备 --chapter 学习 --chapter 回顾` | `课程不存在` | 1 |

实测两条均为 stdout 空、退出码 1。源码依据：`reorder_chapters` 先做 int64
范围检查（`core.py:276-277`，边界常量在 `core.py:46-47`），
`9223372036854775808` = 2⁶³ 超出 SQLite 64 位有符号整数上限，直接返回
`None`；范围内的编号再执行 `SELECT 1 FROM courses WHERE id = ?`
（`core.py:280-284`），查无此行同样返回 `None`。CLI 在
`__main__.py:377-379` 打印 `ERR_NOT_FOUND`（`core.py:12`）并返回 1。
对应测试 `tests/test_reorder_chapters.py:249-261`（`test_unknown_course_id`）。

### 5.3 课程存在但章节列表为空：章节不能为空，退出码 1

| 输入 | 标准错误 | 退出码 |
| --- | --- | --- |
| `reorder-chapters 1`（未提供任何 `--chapter`） | `章节不能为空` | 1 |
| `reorder-chapters 1 --chapter 准备 --chapter "   " --chapter 回顾` | `章节不能为空` | 1 |

实测 stdout 为空、退出码 1，数据不变。源码依据：`--chapter` 缺省为空列表
（`__main__.py:98`）；每个名称先 `strip()`（`core.py:278`），课程存在后
`if not names or any(not name for name in names)` 命中空列表或任一空白名，
抛 `ValidationError(ERR_EMPTY_CHAPTER)`（`core.py:285-286`，常量 `core.py:7`）。
对应测试 `tests/test_reorder_chapters.py:263-284`
（`test_missing_chapter_option`、`test_blank_chapter_for_existing_course`）。

### 5.4 去首尾空白后名称重复：章节名重复，退出码 1

| 输入 | 标准错误 | 退出码 |
| --- | --- | --- |
| `reorder-chapters 1 --chapter 准备 --chapter " 准备 " --chapter 回顾` | `章节名重复` | 1 |

实测 stdout 为空、退出码 1，数据不变。源码依据：空检查之后比较
`len(set(names)) != len(names)`（`core.py:287-288`），针对的是
**strip 之后**的名称，因此仅首尾空白不同的两个名称视为重复，抛
`ValidationError(ERR_DUP_CHAPTER)`（常量 `core.py:9`）。对应测试
`tests/test_reorder_chapters.py:286-301`（`test_duplicate_chapter_rejected`）。

### 5.5 章节列表与现有章节不一致：退出码 1

课程存在、名称非空且无重复时，要求传入名称的**集合**与该课程现有章节名的集合
完全相等（`core.py:289-298`）。下列三类实测均为 stderr
`章节列表与现有章节不一致`、stdout 空、退出码 1、数据不变：

| 情形 | 输入 |
| --- | --- |
| 遗漏现有章节（数量少） | `reorder-chapters 1 --chapter 准备 --chapter 学习` |
| 混入未知名称（数量相同但改名） | `reorder-chapters 1 --chapter 准备 --chapter 学习 --chapter 预习` |
| 多出名称（数量多） | `reorder-chapters 1 --chapter 准备 --chapter 学习 --chapter 回顾 --chapter 测验` |

大小写不同同样按未知名称处理：在含 `Reading`、`Writing` 两章的课程上提交
`reading`、`Writing`，实测报同一条消息（测试
`tests/test_reorder_chapters.py:194-208`）。消息常量
`ERR_CHAPTER_LIST_MISMATCH` 在 `core.py:10`，抛出于 `core.py:297-298`。
对应测试 `tests/test_reorder_chapters.py:303-347`
（`test_missing_existing_chapter`、`test_unknown_chapter_name`、
`test_extra_chapter_name`）。

### 5.6 判定次序（小样例）

判定顺序固定为 **编号格式 → 课程存在性 → 空章节 → 名称重复 → 列表一致性**，
多问题并存时只报最靠前的一个：

1. **编号格式**最先在 CLI 层判定，先于存储调用：`reorder-chapters abc`
   即使完全不带 `--chapter`，实测只报 `课程编号必须为正整数`（退出码 2），
   不会报章节为空。测试 `tests/test_reorder_chapters.py:349-367`。
2. **课程存在性**在存储函数内先于一切章节检查（`core.py:280-284` 先于
   `:285-298`）：`reorder-chapters 42` 不带章节，实测只报 `课程不存在`
   （退出码 1）；未知编号配空白或重复章节名同样只报该条。课程不存在时即使
   章节列表为空也不抛 `ValidationError`。测试
   `tests/test_reorder_chapters.py:369-387`。
3. **空章节**先于重复（`core.py:285-286` 先于 `:287-288`）：提交
   `"   "`、`准备`、`准备` 时实测只报 `章节不能为空`。测试
   `tests/test_reorder_chapters.py:389-404`。
4. **名称重复**先于列表一致性（`core.py:287-288` 先于 `:297-298`）：提交
   `准备`、`准备`、`预习`（既有重复又含未知名称）时实测只报
   `章节名重复`。测试 `tests/test_reorder_chapters.py:406-421`。

### 5.7 「不改变原数据」的保存边界

- **数据行层面**：第 5.1 节在调用存储函数前返回；第 5.2 节在任何 UPDATE 之前
  返回 `None`；第 5.3–5.5 节的三道校验（`core.py:285-298`）全部位于平移与
  落位 UPDATE（`core.py:300-309`）之前，抛错时尚未执行写入。因此这些失败不
  改变 `courses`、`chapters` 的任何行，更不涉及 `enrollments`。实测每个失败
  后课程 1 仍为准备、学习、回顾。
- **文件/表结构层面**：`connect()` 先于编号解析与全部校验执行
  （`__main__.py:224` 先于 `:332` 与 `:373`）。因此对一个**全新路径**执行
  失败的重排（例如对不存在的库执行 `reorder-chapters abc …`）仍会留下已建表
  的空数据库文件——「不改变数据」不等于「不创建数据库文件和表」；对已存在的
  库执行失败调用则无此区别。

## 6. 写入中途失败的原子性（IntegrityError 回滚）

第 5 节的失败是**输入校验失败**，以 `ValidationError` 报告；本节是另一类：
输入列表合法，但写入过程中被 SQLite 约束中止。

### 6.1 现有原子性测试所约定的行为（阅读测试源码，未执行）

`tests/test_reorder_chapters_atomic.py` 直接调用
`course_progress.core.reorder_chapters`（文件头说明见第 1–19 行），其手法是
安装临时触发器 `fail_last_chapter_landing`（SQL 见第 45–52 行）：在课程 1 按
「回顾、准备、学习」落位时，于最后一章「学习」写入 `position = 2` 的那一刻
`RAISE(ABORT, ...)`。由于 `reorder_chapters` 先整体平移、再逐章落位
（`core.py:300-309`），触发器触发时平移与前两次落位已在同一事务内发生，属于
写入中途的约束失败，而非输入不合法。

阅读其断言，该测试约定（本文未运行该测试，以下为测试源码所表达的契约）：

- 存储调用**原样抛出 `sqlite3.IntegrityError`**：异常类型严格为
  `sqlite3.IntegrityError`，且**不是** `ValidationError`，不返回成功详情，
  异常消息措辞不与 SQLite 版本绑定
  （`tests/test_reorder_chapters_atomic.py:129-136`）；
- **位置变化整体回滚**：同一连接与关闭重开后的独立连接上，课程 1 仍为
  准备、学习、回顾，保存的 `position` 与操作前逐行一致，课程 2 与全部课程
  概览也保持原值，无部分重排残留（`:161-174`，行级核对方法 `:138-159`）；
- 撤销故障（`DROP TRIGGER`）后在原连接重试同一合法顺序应成功并持久化
  （`:176-192`）；
- 触发器以 `WHEN NEW.course_id = 1` 限定，故障期间课程 2 的重排不受影响
  （`:194-204`）。

### 6.2 源码推导：为什么会回滚、为什么是 IntegrityError

- 全部写入位于同一个 `with conn:` 事务（`core.py:279`）；函数只捕获
  `ValidationError` 这一自身定义的异常，不捕获 `sqlite3` 错误。约束失败时
  SQLite 抛出 `sqlite3.IntegrityError`，异常逃逸出 `with` 块，连接上下文
  管理器即回滚整个事务，平移与已完成的落位一并撤销。
- 因为只 UPDATE `position` 且最终集合不变，回滚后章节名称、数量与位置区间
  都与操作前相同。

### 6.3 命令行错误处理保持原状（实测）

CLI 分派处只捕获 `ValidationError`（`__main__.py:374`），对存储层
`sqlite3.IntegrityError` **没有**转换或兜底，本次撰写时在临时库安装同一临时
触发器、以独立子进程实测确认这一原状保持不变：

- 退出码为 **1**（Python 对未捕获异常的默认退出码）；
- 标准输出为空；
- 标准错误为完整 Python 堆栈（含 `Traceback`），末行为
  `sqlite3.IntegrityError: 测试故障：拒绝课程 1 最后一章落位`——形态与第 5
  节校验失败的「单行中文消息、无堆栈」不同，尽管两者退出码都是 1；
- 随后另起进程 `get-course 1`，章节仍为准备、学习、回顾，回滚已落库。

如实注明：触发器不属于产品代码路径，正常使用中没有内置方式触发该错误；实测
用触发器仅建在 `mktemp` 临时库中，随临时目录删除，未修改产品代码、表结构或
任何既有数据库。原子性测试对故障期课程 2 不受影响的约定见 6.1，本节实测只
复现了课程 1 的失败与回滚。
