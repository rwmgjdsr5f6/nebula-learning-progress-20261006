## 2. 调用形式与数据库定位

与登记、查询完全相同的约定：

- 通过 `python -m course_progress` 调用，每次用 `--db` 指定数据库文件。
- **父目录必须预先存在**；数据库文件不存在时会自动建库建表
  （`core.py:86-90` 的 `sqlite3.connect(db_path)` + `_SCHEMA` 建表脚本）。
- **`--db` 写在子命令前后均可**：全局 `--db` 定义于 `__main__.py:49`，
  `reorder-chapters` 子命令级的 `--db` 定义于 `__main__.py:93`；测试
  `tests/test_reorder_chapters.py:215-219`（`test_db_option_after_subcommand`）
  覆盖子命令后的写法。
- 子命令语法（`__main__.py:90-100`）：

  ```
  reorder-chapters <course_id> [--chapter <章节名>]...
  ```

  `course_id` 为位置参数；`--chapter` 可重复（`action="append"`），
  **出现顺序即新的章节顺序**，且须与该课程现有章节一一对应。

## 3. 流程总览：从参数到详情返回

一次 `reorder-chapters` 调用串起以下环节（均为源码推导）：

1. **参数解析**（`__main__.py`）：`argparse` 把重复的 `--chapter` 按出现顺序
   收集为列表（`:95-100`）；`parse_positive_int`（`:184-190`）先把位置参数
   `course_id` 解析为正整数，非法时在 `:332-335` 报错并以退出码 2 结束，
   不进入分派。
2. **课程存在性**（`core.py:276-284`）：`reorder_chapters` 先做 int64 范围
   检查，再查 `courses` 表；不存在返回 `None`，CLI 在 `__main__.py:377-379`
   报「课程不存在」并以退出码 1 结束。
3. **章节匹配**（`core.py:285-298`）：依次校验列表非空且各名称去首尾空白后
   非空、无重复、与现有章节集合一致；任一失败抛出 `ValidationError`，CLI 在
   `__main__.py:374-376` 捕获并打印消息，退出码 1。
4. **保存**（`core.py:299-309`）：先把该课程全部章节的 `position` 整体平移
   避开主键冲突，再按新顺序逐章落位；全部写入在同一个 `with conn:` 事务中
   提交（事务从 `:279` 开始）。
5. **详情返回**（`core.py:310` → `__main__.py:380`）：重排完成后调用
   `get_course` 重新读取并返回课程详情，CLI 用 `json.dumps` 打印为一行
   JSON，退出码 0。

## 4. 成功示例：把「入门培训」重排为「回顾、准备、学习」

固定样例：在仓库根目录使用**新数据库** `sample.db`（父目录已存在），通过
现有登记入口保存编号为 1 的「入门培训」，章节依次为准备、学习、回顾。
以下命令均在仓库根目录执行，均为本次实测。

### 4.1 登记样例课程

```bash
python -m course_progress --db sample.db add-course --title "入门培训" --chapter "准备" --chapter "学习" --chapter "回顾"
```

实测标准输出（退出码 0，标准错误为空）：

```json
{"course_id": 1}
```

### 4.2 重排章节

```bash
python -m course_progress --db sample.db reorder-chapters 1 --chapter 回顾 --chapter 准备 --chapter 学习
```

实测结果：

- 退出码 **0**，标准错误**为空**，标准输出**仅一行** JSON，结构与
  `get-course` 查询结果完全相同：

  ```json
  {"course_id": 1, "title": "入门培训", "chapters": ["回顾", "准备", "学习"]}
  ```

  如实注明：`json.dumps` 默认分隔符使实际字节中冒号后带空格
  （`__main__.py:380`）；测试按解析后的 JSON 比较，不限定键序与空格
  （`tests/test_reorder_chapters.py:117-141` 的 `assert_reorder_success`）。
- 该返回值即 `reorder_chapters` 末尾 `get_course(conn, course_id)` 的结果
  （`core.py:310`），与下一条查询命令的输出同一来源、同一结构。

### 4.3 随后查询详情（重新打开同一文件）

```bash
python -m course_progress --db sample.db get-course 1
```

实测标准输出（退出码 0，标准错误为空）：

```json
{"course_id": 1, "title": "入门培训", "chapters": ["回顾", "准备", "学习"]}
```

重排进程已退出，新的 `get-course` 进程重新打开同一 `sample.db`，读到的
章节顺序仍为**回顾、准备、学习**——顺序已持久化。源码依据：章节写入在
`with conn:` 事务中提交（`core.py:279,300-309`），详情查询按
`SELECT name FROM chapters WHERE course_id = ? ORDER BY position`
（`core.py:393-399`）取回，顺序由 `position` 列决定。对应测试
`tests/test_reorder_chapters.py:159-174`
（`test_reorder_persists_across_processes`，跨进程验证）。

### 4.4 不变量与相互隔离

- **课程编号、标题、章节名称与数量不变**：`reorder_chapters` 只执行
  `chapters` 表的 `UPDATE ... SET position`（`core.py:300-309`），不触碰
  `courses` 表，也不增删章节行（源码推导）。实测 4.2/4.3 的 JSON 中
  `course_id`、`title` 与登记时一致，章节仍是原来的三个名称。
- **提交原顺序也成功**：实测在 4.2 之后再执行
  `reorder-chapters 1 --chapter 回顾 --chapter 准备 --chapter 学习`
  （即按当前顺序重复提交），退出码 0、标准错误为空，输出与 4.2 相同，
  内容不变。对应测试 `tests/test_reorder_chapters.py:210-213`
  （`test_same_order_submission_succeeds`）。
- **其他课程和报名关系不受影响**：重排的 UPDATE 均带
  `WHERE course_id = ?`（`core.py:300-309`），只写目标课程的章节行；
  `enrollments` 表完全不被触碰（源码推导）。实测：在同一 `sample.db` 中
  另登记编号 2 的课程「进阶培训」（一章「总览」）、学员「学员甲」及其对
  两门课程的报名关系后执行 4.2 的重排，随后 `get-course 2` 仍返回
  `{"course_id": 2, "title": "进阶培训", "chapters": ["总览"]}`，
  `list-course-learners 1` 与 `list-learner-courses 1` 的名册与报名列表
  均与重排前一致。对应测试
  `tests/test_reorder_chapters.py:159-174`（断言编号 2 详情逐项不变）与
  `tests/test_reorder_chapters_atomic.py:194-204`
  （故障期间课程 2 的重排不受影响）。

## 5. 章节名的处理与匹配规则

对应 `core.py:262-310` 的 `reorder_chapters`（源码推导，均有测试佐证）：

1. **只去首尾空白**：`names = [name.strip() for name in chapters]`
   （`core.py:278`）。内部空白与大小写**原样保留**；与现有章节比较、以及
   最终落位写入用的都是去首尾空白后的名字。测试
   `tests/test_reorder_chapters.py:176-192` 用 `" 总结 "`、`"  阶段  复习  "`
   验证匹配后保存的仍是库中原名（内部双空格保留）。
2. **大小写敏感的精确匹配**：现有章节按位置取出后与提交列表做普通 Python
   字符串/集合比较（`core.py:289-298`），大小写不同即视为不同名称。测试
   `tests/test_reorder_chapters.py:194-208`：已有 `Reading` 时提交
   `reading` 被判为未知名称，报「章节列表与现有章节不一致」。
3. **一一对应**：去空白后的提交列表与现有章节做**集合相等**判断
   （`core.py:297`），数量不符、遗漏、改名或混入未知名形都不通过；
   通过校验后给出的顺序即新的章节顺序。
4. **保存方式**：先把该课程全部 `position` 整体加上章节数平移
   （`core.py:300-303`），避开 `(course_id, position)` 主键冲突，再按新顺序
   从 0 开始逐章落位（`core.py:304-309`），落位后 `position` 仍连续。

## 6. 失败示例（仅本次重排）

`sample.db` 上执行，命令前缀
`python -m course_progress --db sample.db` 省略）。所有失败情形共同的可
观察结果（实测逐条确认）：

- **标准输出为空**；标准错误只有一行中文消息，**不显示异常堆栈**
  （`main` 对 `ValidationError` 的捕获在 `__main__.py:374-376`，编号与
  存在性错误分别在 `:332-335`、`:377-379`；测试
  `tests/test_reorder_chapters.py:143-151` 的 `assert_reorder_failure`
  逐条断言空 stdout、唯一消息、无 `Traceback`）；
- **原数据不变**：上述失败执行后实测 `get-course 1` 仍返回
  `{"course_id": 1, "title": "入门培训", "chapters": ["回顾", "准备", "学习"]}`；
  测试 `tests/test_reorder_chapters.py:153-157` 的
  `assert_state_unchanged` 在每个失败用例后校验两门课程详情与概览。

### 6.1 编号不是正整数：退出码 2

| 输入 | 标准错误 | 退出码 |
| --- | --- | --- |
| `reorder-chapters 0 --chapter 回顾 --chapter 准备 --chapter 学习` | `课程编号必须为正整数` | 2 |
| `reorder-chapters -3 --chapter 回顾 --chapter 准备 --chapter 学习` | `课程编号必须为正整数` | 2 |
| `reorder-chapters abc --chapter 回顾 --chapter 准备 --chapter 学习` | `课程编号必须为正整数` | 2 |

源码依据：`parse_positive_int`（`__main__.py:184-190`）先 `strip()`，再用
正则 `[+-]?\d+` 做 `fullmatch`，仅接受大于 0 的整数；失败时
`__main__.py:332-335` 输出 `ERR_BAD_ID`（`core.py:13`）并返回 2。

## 7. 写入中途失败的原子性

依据 `tests/test_reorder_chapters_atomic.py`（3 个用例，本次已实际运行
并通过）与 `core.py` 源码：

- **写入中途约束失败会整体回滚**：重排的全部写入在同一个 `with conn:`
  事务中（`core.py:279-309`）。原子性测试用测试触发器在课程 1 按「回顾、
  准备、学习」落位的最后一章写入时制造约束失败——此时整体平移与前两章
  落位已在同一事务内执行，属于写入中途失败；测试断言事务回滚后，同一
  连接与关闭重开的独立连接上课程 1 仍为准备、学习、回顾，保存的
  `position` 与操作前完全一致，没有部分重排状态残留
  （`tests/test_reorder_chapters_atomic.py:161-174`）。
- **抛出的异常类型是 `sqlite3.IntegrityError`，而非 `ValidationError`**：
  存储函数不捕获该数据库错误、不返回成功详情，也不把它伪装成校验失败；
  测试断言异常的确切类型为 `sqlite3.IntegrityError` 且不是
  `ValidationError` 的实例
  （`tests/test_reorder_chapters_atomic.py:129-136`）。
- **命令行错误处理保持原状**：CLI 在 `reorder-chapters` 分派处只捕获
  `ValidationError`（`__main__.py:372-376`），对 `sqlite3.IntegrityError`
  没有任何专门处理（源码推导）；本文不替命令行在该异常下的表现做额外
  宣称。
- 故障撤销后在原连接重试同一合法顺序成功并持久化；故障只针对目标课程，
  其他课程的重排不受影响
