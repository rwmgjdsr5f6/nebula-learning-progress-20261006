## 2. 调用形式与 `--db` 语义

命令语法（`__main__.py:164-174`）：

```
python -m course_progress [--db <文件>] list-course-learners <course_id> [--name-contains <片段>] [--db <文件>]
```

- `course_id` 为必填位置参数，语义为「课程编号（正整数）」（`__main__.py:170`）。
- `--name-contains` 为可选参数，省略时列出该课程全部已报名学员；传入时按
  姓名片段筛选（规则见第 5 节）。CLI 帮助文本（`__main__.py:171-174`）写明
  「去除首尾空白后做大小写敏感的连续子串匹配」。
- 每次用 `--db` 指定 SQLite 数据库文件，**父目录必须预先存在**；文件不存在时
  自动创建并建表（`README.md:7`；`core.py:116-120`）。
- **`--db` 写在子命令前后语义相同**：全局 `--db` 定义于 `__main__.py:49`，
  子命令级 `--db` 定义于 `__main__.py:167-169`（`default=argparse.SUPPRESS`），
  两者都汇入同一个 `args.db`，由 `main` 在 `__main__.py:227` 统一读取。
- 不提供 `--db` 时：标准错误 `必须通过 --db 指定数据库文件`，退出码 2，
  不接触数据库（`__main__.py:228-230`）。

## 5. 筛选词的匹配规则

以下规则全部由 `list_course_learners`（`core.py:615-660`）实现，CLI 层只做
参数传递（`__main__.py:287-290`），不另行加工筛选词：

1. **只去首尾空白，保留内部空白**：规范化只有一步 `name_contains.strip()`
   （`core.py:638`）。内部空格、制表符原样参与匹配。回归测试
   `test_internal_whitespace_is_preserved_in_filter`
   （`tests/test_list_course_learners_name_filter.py:224-249`）：把学员 1
   改名为「An n」后，筛选词 `"  An n  "` 去首尾空白命中；而 `"An  n"`
   （两个内部空格）在姓名中不存在，返回空名册。
2. **大小写敏感的连续子串匹配**：匹配在 Python 层以
   `name_contains in learner["name"]` 完成（`core.py:655-659`），对学员
   **当前保存的完整姓名**做子串判断，不分词、不忽略大小写。第 4.3 节的
   「Ann 命中学员 1 而不命中学员 2」即此规则的直接表现。
3. **百分号、下划线、引号都是普通字符**：匹配不走 SQL 的 `LIKE`，`%` 与
   `_` 没有通配含义，引号也不需要转义。回归测试
   `test_percent_underscore_quote_are_literal_characters`
   （`tests/test_list_course_learners_name_filter.py:190-222`）：把学员 1
   改名为 `A%_"n` 后，筛选词 `%`、`_`、`"`、`%_"` 各自只字面命中该学员，
   其中 `%` 不匹配不含百分号的学员 2。
4. **只匹配当前姓名**：姓名取查询时数据库中保存的值
   （`core.py:641-654` 实时 JOIN `learners` 表）。改名
   （`rename-learner`，`core.py:458-481`）后按新姓名筛选，旧姓名不再命中。
   回归测试 `test_rename_then_filter_matches_new_name`
   （`tests/test_list_course_learners_name_filter.py:251-275`）：学员 1
   改名「Beth」后，筛 `Beth` 命中、筛 `Ann` 在课程 1 无匹配。
5. **只在目标课程的已报名学员中筛选**：范围由 SQL 的
   `FROM enrollments AS e JOIN learners AS l ON l.id = e.learner_id
   WHERE e.course_id = ?` 限定（`core.py:641-650`），其他课程的学员与未
   报名学员不可能进入结果。回归测试
   `test_filter_only_applies_to_target_course_enrollments`
   （`tests/test_list_course_learners_name_filter.py:168-188`）：在课程 2
   上筛 `Ann` 只命中只报名了课程 2 的学员 3（不含同名的学员 1），筛 `ann`
   返回空名册（学员 2 未报名课程 2）。
6. **同名学员按编号区分**：名册单项以 `learner_id` 为身份
   （`core.py:651-654`），排序为 `ORDER BY l.id`（`core.py:647`）。若学员
   1 与学员 3 报名同一课程，两个「Ann」会作为两个编号不同的条目分别出现。

## 6. 空结果的两种正常情形

以下两种情形都不是错误，标准错误为空、退出码 0，`learners` 为空数组：

| 情形 | 预期标准输出 | 依据 |
| --- | --- | --- |
| 课程存在但无人报名 | `{"course_id": N, "learners": []}` | 报名范围读取得到 0 行（`core.py:641-654`），正常返回空列表 |
| 有人报名但筛选词无匹配 | `{"course_id": N, "learners": []}` | 匹配过滤后为空（`core.py:655-659`） |

在样例库中，课程 2 上筛 `"ann"` 即第二种情形：学员 2「ann」未报名课程 2，
预期输出 `{"course_id": 2, "learners": []}`，退出码 0。回归测试
`test_no_match_returns_empty_roster`（第 277–283 行）与
`test_course_without_enrollments_returns_empty_roster`（第 285–300 行，
含无人报名课程在省略筛选词与带筛选词下均返回空名册）分别覆盖。

注意与「课程不存在」严格区分：后者标准输出为空、标准错误 `课程不存在`、
退出码 1（见第 7 节），不输出任何 JSON。

### 7.1 三类失败的输入、消息与退出码

  加 `return` 处理，空筛选词抛出的 `ValidationError` 在
  `__main__.py:291-293` 被捕获并转为消息，不存在未捕获异常。回归测试统一
  断言 stdout 为空、消息精确相等、stderr 不含 `Traceback`：格式类在
  `test_non_positive_or_non_numeric_id_exits_2`（第 349–358 行，含 `0`、
  `-1`、`abc`），不存在类在
  `test_unknown_course_reports_not_found_even_with_empty_filter`
  （第 323–334 行）与 `test_overflow_course_id_reports_not_found`
  （第 336–347 行），空筛选词类在
  `test_empty_filter_exits_1_with_message_and_no_traceback`
  （第 302–310 行）与 `test_whitespace_only_filter_exits_1_with_message`
  （第 312–321 行）。

### 7.2 优先级：编号格式 → 课程存在性 → 筛选词非空

多种问题同时存在时只报告首个错误，顺序由代码结构固定：

1. **先查编号格式**（CLI 层）：`parse_positive_int` 在调用 core 之前执行
   （`__main__.py:283`），非法编号根本不会进入 core，即使筛选词为空也只报
   `课程编号必须为正整数`、退出码 2。
2. **再查课程存在性**（core 层）：`list_course_learners` 先做范围检查与
   存在性查询（`core.py:630-636`），**然后才**规范化筛选词
   （`core.py:637-640`）。因此课程不存在时即使筛选词为空或全为空白，也
   只报 `课程不存在`、退出码 1，不抛 `ValidationError`。回归测试
   `test_unknown_course_reports_not_found_even_with_empty_filter`
   （`tests/test_list_course_learners_name_filter.py:323-334`）对
   `999` 分别搭配省略筛选词、空筛选词、正常筛选词三种情形断言同一结果；
   函数层 `test_function_unknown_course_returns_none_even_with_empty_filter`
   （第 468–476 行）进一步断言空筛选词下返回 `None` 而不抛异常。
3. **最后查筛选词非空**：只有课程存在时，空或全空白筛选词才报
   `学员姓名筛选词不能为空`、退出码 1。

`9223372036854775808`（2^63）超出 SQLite 64 位有符号整数范围，不可能对应
任何课程，按「课程不存在」处理（`core.py:630-631`），与 `999` 同属第二级；
这与 README 第 168、195 行记载的其他命令行为一致。

## 8. 持久化、重开与只读边界

- **每条 CLI 命令都是独立进程**：再次执行同一查询（等价于关闭后重开
  `sample.db`），预期结果与首次完全相同。报名关系由 `enroll_learner` 在
  自己的事务中提交（`core.py:550-559`），之后仅被读取。函数层回归测试
  `test_reopen_same_file_keeps_filter_results_consistent`
  （`tests/test_list_course_learners_name_filter.py:490-499`）显式关闭并
  重新打开同一文件，断言筛选结果与省略筛选词的结果均保持一致。
- **改名后按新姓名筛选**：姓名不做快照，名册每次实时读取 `learners` 表
  （见第 5 节规则 4）；重开同一库后改名结果同样保持。
- **查询是业务只读操作**：`list_course_learners` 中只有 `SELECT`
  （`core.py:632-650`），没有 INSERT/UPDATE/DELETE；CLI 虽在 `with conn:`
  中分派（`__main__.py:236`），但本分支无任何写入可提交。回归测试
  `test_queries_do_not_change_business_data`
  （`tests/test_list_course_learners_name_filter.py:360-379`）在成功筛选、
  空筛选词失败、课程不存在失败三类调用前后，比对课程、章节、学员、报名
  四张表的全部内容完全一致；函数层同名测试（第 478–488 行）覆盖同一结论。
- **首次查询可能建库建表，但不改变业务记录**：`main` 在分派到任何子命令
  分支前先执行 `connect(db_path)`（`__main__.py:232`，先于第 283 行的编号
  解析）。`connect` 中的 `sqlite3.connect` 在文件不存在时创建空文件，随后
  `executescript(_SCHEMA)` 以 `CREATE TABLE IF NOT EXISTS` 建表
  （`core.py:116-120`，DDL 文本 `core.py:19-39`）。因此对一条全新路径执行
  本查询会留下已建表的数据库文件（随后按第 7 节报告 `课程不存在`），但
  四张业务表均为 0 行——建表 DDL 与业务记录是两个层面，前者不属于
  「修改业务数据」。唯一连文件都不创建的失败是 argparse 阶段拒绝（缺少
  位置参数，`connect` 尚未执行）。
- **不同 `--db` 文件彼此独立**（`README.md:201`）。

## 9. 核对结论

- 第 4.3 节的成功 JSON（`" Ann "` 只命中学员 1、`"ann"` 只命中学员 2）、
  退出码 0、空标准错误、单行输出，分别对应 `__main__.py:282-303` 与
  `core.py:615-660`，并由
  `tests/test_list_course_learners_name_filter.py:119-147` 锁定。
- 筛选词只去首尾空白、保留内部空白、大小写敏感连续子串匹配、百分号/
  下划线/引号为普通字符，由 `core.py:637-640,655-659` 实现，回归测试第
  190–249 行覆盖。
- 筛选只作用于目标课程已报名学员、同名学员按编号区分、省略筛选词时按
  编号升序列出全部，由 `core.py:641-654` 的 SQL 与字典结构保证，回归测试
  第 149–188 行覆盖。
- 错误优先级「编号格式（退出码 2）→ 课程不存在（退出码 1，含
  `9223372036854775808`，即使筛选词为空也先报此错）→ 筛选词为空
  （退出码 1）」由 `__main__.py:283-296` 与 `core.py:630-640` 的执行顺序
  固定，三类失败均标准输出为空、无异常堆栈，回归测试第 302–358 行覆盖。
- 课程存在但无人报名或无匹配项时返回空 `learners` 数组、退出码 0
  （`core.py:641-659`），与课程不存在是两条互斥路径。
- 改名后按新姓名筛选、重开同一库结果一致、查询业务只读、首次查询仅可能
  建库建表而不改变业务记录，见第 5、8 节及所引源码与测试。
